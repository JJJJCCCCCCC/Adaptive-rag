# 按证据决定检索轮数的配对实验

## 研究问题与当前证据

在有跨表收费、期限和多级条款引用的店铺政策库中，按第一轮证据决定是否补查，能否提高相对固定单轮的答全率，并以较少的模型用量达到固定三轮的样本得分？实验结果可以支持、部分支持或不支持该假设。旧 30 题用于定位和开发；新版的 36 题在正式调用前固定，不用其胜负调参。开发者参与出题，因此这是合成场景的留出测试。

旧题 M08 开发回放复用了历史 DeepSeek 运行实际给出的前两轮改写和第一轮证据评估，在原知识库中执行新版检索：第二轮实际以 R71 查到券额表，最终三份证据同时包含商品档案和「R71 返6元券」。回放没有重新生成答案，亦未计入下述 36 题。

另外，对旧 30 题固定三轮的真实 DeepSeek 轨迹做同前缀回放：在首次判够时截断，逐题核对该轮证据与三轮结束时的证据。29 题首轮判够，1 题到第三轮仍未判够。由此将实际 90 轮折算为 32 轮，少 58 轮；两种截取方式均有 29/30 题找齐所需文档，每题的证据齐全与否也完全一致。该分析固定了旧查询轨迹，仅衡量停止时机与证据覆盖；节约的实际 token、端到端时延和新版的答全率均须单独实测。

## 预先固定的对照与判据

36 题使用 58 篇新虚构条款。题型依次为单文档事实或条件计算 10 题、需要关联服务编号 10 题、需要关联条款名称 6 题、跨三份文档 4 题、库内缺少答案 4 题、范围外 2 题。20 道跨文档题是有意提高比例的压力场景。一个查询可能一次召回多篇目标文档，各组均有机会首轮答全。数据 SHA-256 为 `c36a1ada7f566adc0ad26eadbe1666b6ae47a83db1b442c1dc8539806418978b`。

所有策略使用同一意图与复杂度路由、预检通过的 DeepSeek、查询改写、混合检索、词面重排、回答和护栏。在进入检索的题目上，固定单轮只做一轮；固定三轮总做三轮；自适应在一至三轮之间由已有证据决定。三组的每轮最多两个查询、每查询取前三、生成前最终最多保留三个片段。首轮可做语义改写。后续轮次优先查证据中已经出现且与缺失事实关联的编号、具名条款或缺失条件。固定三轮也能用同一规则。范围外等未进入检索的分支允许零轮。真实部署中的路由误判也计入每组总成绩。每个策略独立运行项目图，按题打乱次序，因而模型输出可能有随机差异。

| 判断 | 运行前设定的标准 |
| --- | --- |
| 比固定单轮答得好 | 36 题总通过数更高，逐题配对的双侧精确 McNemar 检验 p < 0.05，同时公开救回和新增错误的题号。 |
| 比固定三轮省 | 自适应的样本总通过数至少持平，正式问答的总 token 至少少 20%。记录检索轮数、实际模型调用数和延迟。该项是样本上的工程门槛。 |
| 拒答对照 | 4 道无答案题均承认无法确定，2 道域外题均恰当拒绝或引导。 |
| 总体解读 | 三项同时满足才报告在本压力场景达到预设目标。仅通过某一项就只报告该项；不根据结果更改阈值。 |

主要指标为最终答案。预置参考答案规定数值、单位和适用条件。答不全或编造承诺计为失败。每题三个回答匿名打乱顺序后交给同一 DeepSeek 评审，评审仅看到问题、条款、参考答案和匿名回答，按统一规则返回逐答理由。评审用量单列。建议逐题核对改变结论的样本，尤其是拒答或夹带额外承诺的回答。单一模型评审、每题每臂一次、合成题和共享题型模板均限制外推。全题集的配对检验不能代表实际客流分布。汇总另给出每多答对一题的增量 token，以便判断收益是否值得；净收益非正时此项无定义。

## 运行与产物

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m eval.evidence36
```

先以随机校验串验证官方 API 的真实回答、模型标识、完成 ID 和用量。正式运行 108 个题目与策略组合，随后 36 次匿名评审。每个组合与对应的 HTTP 200 回执及 token 数核对后落盘。脚本按完成组合和已评题目断点续跑。首轮测试时受管会话的真实 API 预检返回 ConnectError，正式指标待可联网环境执行。

完成后查看 `eval/results/evidence36-live/summary.json` 和 `review.csv`。前者给出三组指标、配对检验和各项门槛判断；后者含题面、标准答案、实际回答、判分理由、检索轮数和用量。每题每策略的 JSON 中还保留模型路由和各轮改写、检索查询及证据。

候选逻辑位于项目的真实检索节点，配置项 `evidence_guided_retrieval` 默认关闭，仅本实验自动启用。线上默认策略是否切换等正式成绩出来再决定。

## 本机正式问答与独立复核

108 份正式回答均已保存。每份的题号、策略、运行指纹、调用数和 token 已核对，共有 707 条唯一的 HTTP 200 回执，返回模型为 `deepseek-flash`。原版 DeepSeek 评审在第一题校验响应结构时中止，未保存那次响应，也未产生有效评分。修复后的入口可用 `python -m eval.evidence36 --grade-only` 单独续评。它记录评审返回正文及回执；不合格式时先重试整题，再按匿名候选逐个补评，仍缺失的判断会报错。旧版失败评审的用量无法还原。

以下质量得分由 Codex 按相同标准对 108 个匿名候选逐条复核后解盲。预设的 DeepSeek 评审尚待在可联网环境续跑，完成后会生成独立的 summary.json 和 review.csv。

| 策略 | 通过 | 总检索轮数 | 正式回答 token | 单题中位耗时 |
| --- | ---: | ---: | ---: | ---: |
| 固定单轮 | 18/36 | 31 | 64,131 | 4.78 秒 |
| 固定三轮 | 21/36 | 93 | 90,834 | 8.13 秒 |
| 自适应 | 24/36 | 63 | 83,931 | 7.05 秒 |

相对单轮，自适应多答对 H11、H13、H18、H19、H21、H24，新增答错 0 题，双侧配对精确检验 p=0.03125。每净增一题消耗 3,300 个额外 token。H11 的第二轮用 LX-218 检出盖件备料账，给出了 23 元。相对固定三轮，实际 token 减少 7.60%，低于预定的 20% 门槛。三组在缺证据和域外的 6 道对照题上均通过，在需串联三份文档的 4 道题上均未答全。当前复核支持在本题集上提高相对单轮的回答质量，总体预设目标尚未全部达到。
